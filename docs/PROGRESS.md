## Decisions log
- **Cache Components off** (`next.config.ts`). Next 16 scaffolds it on; with it on, every session read must sit inside `<Suspense>` or the build fails. All pages here are per-user, so the classic per-request rendering model is simpler and easier to explain.
- **bcryptjs** instead of native `bcrypt`: same algorithm and hash format, no native build step on Windows or Vercel.
- **Login uses a server action** calling `signIn(..., { redirect: false })` so the form can show a toast and then navigate; `/` is redirected to the role's dashboard by the proxy.
- **Accessibility over the design:** success/warning text uses darker tokens (`#15803D`, `#B45309`, both 5.0:1 on white) because the spec colours are only ~3.2:1. Input borders use `#8A91A5` (3.15:1) to meet the non-text contrast rule. Buttons and inputs are 40px tall.
- **Seed emails use the reserved `.test` TLD** so no real address can receive mail.
- **Unit tests run against the Neon database** for services (added from Phase 2). Each test creates and cleans up its own uniquely named rows.
- **Admin data views are client components using TanStack Query against `/api/*`.** Server pages only check the role. This keeps the layer rule (UI -> API -> services) and gives every view the same loading, error-with-retry and empty states.
- **API responses use ISO date strings** in their DTO types, so client types match what JSON actually carries.
- **Completions chart counts all completions** (including learners deactivated since), because those completions happened. The KPI and per-activity rates follow the active-learner definitions exactly.
- **Bulk assignment writes one audit entry per assign action** (with added/skipped counts) rather than one per learner.
- **Known gap until Phase 8:** the "Audit log" nav item 404s until the audit page is built (Phase 8.2). The learner "My progress" link was fixed in Phase 4.
- **Seed now replays action lists through the real engine** (Phase 1 used hand-written histories). Demo attempts are matched by their fixed seed and refreshed in place on re-seed; assignments with real attempts are skipped.
- **The scenario data never reaches the browser bundle.** Client components import `scenarios/catalog.ts` (keys, titles, fault names only); a unit test keeps it in sync with the scenario file.
- **Every simulation action writes an audit entry** (`simulation.action`). The dashboard feed hides these as noise; the audit page will show them.
- **Locked actions reveal a little information** (e.g. "Reseat the RAM" stays locked if listening finds no beep code). This is intentional and realistic: no beep code means memory isn't the suspect.
- **Efficiency bonus follows the spec literally:** solved in 6 actions or fewer earns +10, even if those actions included penalties (seeded Ethan: 67 + 10 = 77).
- **Flaky tests: root causes found and fixed (Phase 6).** (1) The "fault never sent early" test failed whenever the random seed chose CPU overheating, because that fault's name is inside the always-shown label "Diagnose: CPU overheating". The test now ignores action labels, and a new database-free test checks all three faults explicitly. (2) Timeouts against remote Neon (~210 ms per query from here): Prisma's interactive-transaction defaults (2s to start) were too tight, giving `Unable to start a transaction in the given time`. The client now uses `maxWait 10s / timeout 20s`, and Vitest hook/test timeouts are 60s. After the fixes: 3 consecutive isolated runs passed 71/71. (3) Timed-out tests left fixture data behind, which then broke other tests (wrong activity picked, learner pushed to page 2). Added `npm run db:clean-tests` and a Playwright global teardown.
- **Learner read endpoints live at `/api/assignments/mine` and `/api/stats/me`**, keeping the spec's API folders. Every query in `learner-portal.service` is scoped by the signed-in learner's id.
- **E2E tests don't import Prisma:** Playwright loads tests as CommonJS and the Prisma 7 client is ESM-only, so e2e tests get their data through the app's own API as a real user would.
- **`AUTH_TRUST_HOST` for non-Vercel production.** Running `next start` locally failed every login with Auth.js `UntrustedHost`. Vercel is trusted automatically, so nothing is hard-coded; the variable is documented in `.env.example` and the README for self-hosted runs.
- **Phase 5 commit went out with a failing unit run.** My check pipeline piped `npm test` through `grep`, which hid the non-zero exit. That commit only changed docs and config; the failure was flaky issue (1) above, fixed in Phase 6. I now check each command's exit code before committing.
- **Vercel region pinned to `fra1`** (Frankfurt) in `vercel.json`, next to the Neon database in eu-central-1. Vercel's default US-East region would add a transatlantic round trip to every query.
- **Restart your local dev server** after pulling Phase 6: `db.ts` caches the Prisma client on `globalThis` across hot reloads, so a server started before this change keeps the old 2s transaction limit (that's what made one admin "create learner" call return 500 during testing).
- **Assignment audit entries now record `learnerIds`** (who actually received the activity), which also lets the test cleanup find e2e entries.
